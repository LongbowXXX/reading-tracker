# 漫画喫茶 読書記録アプリ 要求定義書

作成日: 2026-08-30
版数: 0.1（初版・分析段階）

---

## 1. 背景と目的

漫画喫茶で漫画を読む際、以下の課題が発生している。

| #   | 課題                                         | 発生する場面 |
| --- | -------------------------------------------- | ------------ |
| 1   | 何巻まで読んでいたか忘れる                   | 来店時       |
| 2   | 読みたかった本のタイトルを忘れる             | 来店時／日常 |
| 3   | 新刊が出ているかわからない                   | 日常         |
| 4   | その店で目当ての本がどの棚にあるかわからない | 来店時       |

課題1〜3は既存の漫画管理アプリ（コミックログ、ベルアラート、読んだ。等）でおおむね対応可能である。
一方、課題4は**店舗ごとの物理的な配架情報**という軸を必要とし、既存アプリはこの概念を持たない。
また既存アプリはいずれも「購入・所蔵」を前提としたデータモデルであり、「買わずに読むだけ」という漫画喫茶の利用形態と噛み合わない。

本アプリは、この2点を解決することを目的とする。

---

## 2. 用語定義

| 用語   | 定義                                               |
| ------ | -------------------------------------------------- |
| 作品   | シリーズ単位の漫画作品。複数の巻を持つ             |
| 巻     | 作品を構成する個々の単行本。ISBNで一意に識別される |
| 店舗   | 個々の漫画喫茶。チェーン単位ではなく店舗単位で扱う |
| 棚番号 | 店舗が整理用にコミックへ貼付しているシールの番号   |
| 読了   | その巻を最後まで読み終えた状態                     |
| 中断   | その巻を読み始めたが、最後まで読んでいない状態     |
| 離脱   | 以降その作品を読む意思がない状態                   |

---

## 3. 利用シーンと前提

### 3.1 入力が発生する場面

読書記録の入力は、**個室内で本を手に持っている状態**でのみ発生する。
この時点でコミックの裏表紙（バーコード）と棚番号シールが同時に視認できるため、作品の識別と棚番号の入力を一連の操作として完結できる。

### 3.2 前提条件

- 棚番号シールは店舗が整理用に貼付しており、**シリーズで原則同一の番号**である
- 長期連載作品では、巻によって棚が分かれる可能性がある
- 漫画喫茶は**原則として最新刊まで配架している**（配架上限の管理は不要とする）
- 店舗のレイアウト変更により、棚番号は変わりうる
- 個人利用を前提とする（配架情報の他ユーザーとの共有は行わない）
- 端末は**オンデバイス AI が動作するもの**に限る。作品の同定に AI を用いるため、動作しない端末はサポート対象外とする（対応端末は Pixel 9 以降など限られる）
- 漫画喫茶では**店舗の Wi-Fi を利用できる**

### 3.3 制約

- 棚の前で立ったまま操作する運用は行わない（棚全体の一括読み取りはスコープ外）
- 個室ではモバイル回線の電波状況が悪い場合があるため、通信は店舗の Wi-Fi を前提とする
- 棚番号シールがバーコードを覆っている可能性がある（**要実店舗確認**）

---

## 4. 業務ルール

### 4.1 棚番号の継承

- 棚番号は「店舗 × 作品 × 巻」に紐づく
- 新たな巻を記録する際、**直前の巻の棚番号を自動継承**する
- 巻単位で棚番号を変更でき、変更後の番号は以降の巻に継承される
  - 例: 全50巻の作品で31巻から棚が変わった場合、31巻で1回変更すれば32巻以降も新しい番号を引き継ぐ
- 作品単位での一括更新が可能
  - 用途: 店舗のレイアウト変更に伴う訂正／別店舗での初期登録
  - 適用範囲は当該作品の全巻（未読分を含む）
  - **店舗ごとに独立**しており、A店での一括更新はB店の記録に影響しない

### 4.2 読書状態

- 巻ごとに「読了」「中断」のいずれかの状態を持つ
- 巻内の読了位置（ページ・話数）は記録しない。必要に応じてメモで補う
- 作品単位で「離脱」を設定でき、離脱した作品は来店時の一覧から除外される

### 4.3 作品の識別

- 識別はISBN（バーコード上段の13桁）を基本とする
- 入力手段は以下の3通り
  1. バーコード読み取り
  2. ISBNの手入力
  3. 暫定名での記録（後から正式な作品へ紐づけ）
- タイトルのあいまい検索機能は設けない。ブラウザ等の外部手段で調べたうえで入力する運用とする

## 5. 機能要求

### A. 読書の記録

| ID   | 要求                                                   |
| ---- | ------------------------------------------------------ |
| A-1  | 読んでいる巻を記録できる                               |
| A-1a | バーコード読み取りにより入力できる                     |
| A-1b | バーコード番号（ISBN）を手入力できる                   |
| A-1c | 暫定の名前で記録し、後から正式な作品へ紐づけられる     |
| A-2  | 入力されたISBNの妥当性（チェックディジット）を検証する |
| A-3  | 取得した書誌情報を確認・修正したうえで確定できる       |
| A-4  | 巻ごとに「読了」「中断」を区別して記録できる           |
| A-5  | 棚番号を入力できる（直前の巻から自動継承）             |
| A-6  | 巻単位で棚番号を変更できる                             |
| A-7  | 棚番号を未入力のまま記録を保存できる                   |
| A-8  | 記録した内容をその場で確認・修正できる                 |
| A-9  | 作品単位で棚番号を一括更新できる（店舗ごとに独立）     |
| A-10 | 巻ごとにメモを記録できる（中断位置の覚書、感想等）     |

**補足**: A-1a と A-1b は同格の入力手段として扱い、1操作で相互に切り替えられること。棚番号シールがバーコードを覆っているケースが想定されるため、手入力を例外処理として扱わない。

### B. 来店時の参照

| ID  | 要求                                                         |
| --- | ------------------------------------------------------------ |
| B-1 | 店舗を選ぶと、その店で読める読みかけ作品を一覧できる         |
| B-2 | 一覧に棚番号を併記する                                       |
| B-3 | 次に読むべき巻を示す（中断中の巻がある場合はその巻）         |
| B-4 | 棚番号がいつ時点の情報かを示す                               |
| B-5 | 実際と異なる場合に棚番号を訂正できる                         |
| B-6 | 現在地から店舗を自動選択する（手動選択へフォールバック可能） |

**補足**: B-1 が課題1に対する実質的な解となる。「何巻まで読んだかを思い出す」機能ではなく、「この店で今日読める続きを提示する」機能として位置づける。
B-4 はフロア情報等の補足を持たない設計のため重要度が高い。棚番号のみが手がかりであり、情報が古いと目的の本にたどり着けない。

### C. 読みたい作品の管理

| ID  | 要求                                                               |
| --- | ------------------------------------------------------------------ |
| C-1 | 読みたい作品を登録できる（ISBN入力または暫定名）                   |
| C-2 | 読みたい作品を一覧できる                                           |
| C-3 | 読みたい作品が来店中の店舗にあるか確認できる                       |
| C-4 | 作品ごとにメモを記録できる（うろ覚えの手がかり、登録理由、感想等） |

**補足**: C-3 は過去に配架を記録した作品についてのみ判断可能であり、未記録の作品については判定できない。この制約は初期段階で顕著となる。

### D. 新刊の把握

| ID  | 要求                                     |
| --- | ---------------------------------------- |
| D-1 | 記録済み作品の新刊発売を知ることができる |
| D-2 | 読みたい作品の新刊発売を知ることができる |
| D-3 | 未読の巻が発生している作品を一覧できる   |

**補足**: D-3 は通知を見逃した場合の受け皿として機能する。来店時に未読分をまとめて把握できるため、実用上は D-1/D-2 より有用な可能性がある。

### E. 作品の状態管理

| ID  | 要求                                                   |
| --- | ------------------------------------------------------ |
| E-1 | 作品を「離脱」として記録し、来店時の一覧から除外できる |
| E-2 | 離脱した作品を確認・復帰できる                         |

### F. 保守・データ管理

| ID  | 要求                                   |
| --- | -------------------------------------- |
| F-1 | 店舗を登録・編集できる                 |
| F-2 | 作品情報を手動で補正できる             |
| F-3 | 記録を削除できる                       |
| F-4 | 記録を外部に持ち出せる（エクスポート） |
| F-5 | メモを検索できる                       |

### G. 動作環境

| ID  | 要求                                                                                             |
| --- | ------------------------------------------------------------------------------------------------ |
| G-1 | オンデバイス AI が動作しない端末では、その旨を起動時に警告し、機能を利用させない                 |
| G-2 | AI モデルが未取得の端末では、準備状況を提示し、利用者の操作で取得したうえで利用可能とする         |

**補足**: 作品の同定にオンデバイス AI を用いるため、AI が動作しない端末はサポート対象外とする（3.2 前提条件）。G-2 の取得は通信量が大きいため、システムが自動で開始せず利用者の明示的な操作を待つ。

## 6. 課題と機能要求の対応

| 課題                                | 対応する機能要求                         |
| ----------------------------------- | ---------------------------------------- |
| 1. 何巻まで読んでいたか忘れる       | A-1, A-4（記録） / B-1, B-3（参照）      |
| 2. 読みたかった本のタイトルを忘れる | C-1, C-2, C-4                            |
| 3. 新刊が出ているかわからない       | D-1, D-2, D-3                            |
| 4. どの棚にあるかわからない         | A-5〜A-9（記録） / B-2, B-4, B-5（参照） |

## 7. 優先度

### 中核（これだけで課題1・4が解決し、アプリとして成立する）

- A-1〜A-8, A-10
- B-1, B-2, B-3
- G-1, G-2（AI 前提の動作環境。AI が動作しなければ作品の同定が成立しないため中核に含める）

### 次段階

- A-9（一括更新）
- B-4, B-5, B-6
- D-1, D-3
- C-1, C-2, C-4
- E-1, E-2
- F-1〜F-5

### 慎重に扱う

- C-3: 配架情報が蓄積されるまで機能しない。初期はほぼ空振りとなるため、期待値の見せ方を含めて別途検討する

## 8. スコープ外

| 項目                             | 除外理由                                                  |
| -------------------------------- | --------------------------------------------------------- |
| 棚全体の一括読み取り             | 棚前での撮影運用を行わないため                            |
| 購入・所有管理                   | 読むのみで所有しないため                                  |
| 配架情報のユーザー間共有         | 正確性の担保および店舗との関係で別途検討が必要            |
| フロア・通路等の位置補足情報     | 棚番号のみで足りると判断                                  |
| 店舗の配架上限管理               | 原則最新刊まで配架されている前提のため                    |
| タイトルのあいまい検索・候補提示 | ブラウザ等の外部手段で代替                                |
| 読書時間・冊数の統計             | 4つの課題のいずれにも対応せず、記録の手間のみ増加するため |

## 10. 実現手段の検討に向けた留意点（参考）

本書は要求定義であり実現手段には踏み込まないが、後続の検討で論点となる項目を記録しておく。

- **書誌情報の取得**: ISBNからタイトル・著者・出版社・発売日は取得可能。ただし巻数は独立した項目として取得できるとは限らず、タイトル文字列からの抽出または手入力補正が必要になる可能性がある
- **シリーズの同定**: 巻ごとにISBNが異なるため、既存記録との突合方法の検討が必要
- **旧作の扱い**: ISBNの13桁化は2007年。それ以前の10桁ISBN、およびバーコード非搭載の書籍が存在する
- **新刊情報の網羅性**: 未刊行の新刊（発売予定日）を扱えるデータソースは限られる。D群の実現方式は要調査
- **位置情報の精度**: 商業ビル内の店舗では測位精度が低下する可能性があり、B-6 のフォールバックは必須
